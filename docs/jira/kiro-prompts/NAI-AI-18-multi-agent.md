## Description

Design and implement a multi-agent architecture with a supervisor and at least two specialist
agents. All agents share a single `ToolRegistry`. The supervisor delegates sub-tasks and aggregates
results. Safeguards prevent runaway loops and excessive tool execution. Demonstrate a bounded
multi-agent research task completing end-to-end.

## Architecture Rules

- Supervisor delegates — it never executes tools directly.
- Specialists communicate only through the supervisor — no direct specialist-to-specialist calls.
- Shared `ToolRegistry` is constructed once and passed to all agents.
- Each specialist has `max_steps` enforced independently.
- Supervisor has `max_rounds` enforced globally.
- All agents return typed `AgentResult` — no raw strings.
- Cancellation of the supervisor propagates `asyncio.CancelledError` to all running specialists.
- `AgentStatus` covers: `SUCCESS`, `FAILURE`, `STEP_LIMIT_REACHED`, `CANCELLED`.

## Implementation Task

### 1. Agent Protocol

Create `backend/agent-runtime/multi-agent/protocols/agent_protocol.py`:

```python
class Agent(Protocol):
    name: str
    async def run(self, task: str, context: AgentContext) -> AgentResult: ...
```

### 2. Shared Context

Create `backend/agent-runtime/multi-agent/shared/agent_context.py`:
- `AgentContext(task_id: str, shared_memory: list[str])`
- `add_result(agent_name: str, result: AgentResult) -> None`
- `aggregate_results() -> AgentResult` — concatenates all successful outputs

### 3. Specialist Agents

Create `backend/agent-runtime/multi-agent/specialists/`:
- `researcher_agent.py` — retrieves documents using the `ToolRegistry`'s search tool; `max_steps=5`
- `writer_agent.py` — drafts a summary from retrieved content passed via context; `max_steps=3`

Each is a self-contained class implementing `Agent` that uses `AgentExecutor` from NAI-AI-11.

### 4. Supervisor Agent

Create `backend/agent-runtime/multi-agent/supervisor/supervisor_agent.py`:
- Accepts `specialists: dict[str, Agent]`, `router: TaskRouter`, `max_rounds: int = 5`
- `run(task, context)` loop:
  1. Router decides which specialist handles the next sub-task
  2. Calls specialist; stores `AgentResult` in context
  3. If `result.status != SUCCESS`: return immediately with that status
  4. If router returns `None`: aggregation step and return `SUCCESS`
  5. If `round >= max_rounds`: return `STEP_LIMIT_REACHED`

### 5. Task Router

Create `backend/agent-runtime/multi-agent/supervisor/task_router.py`:
- `route(task: str, context: AgentContext) -> str | None`
- Uses the `LLMProvider` to decide which specialist to call next
- Returns `None` when the task is complete

### 6. FastAPI Endpoint

Add `POST /v1/agents/multi/run` to the FastAPI service:
- Accepts `MultiAgentRunRequest(task: str, max_rounds: int = 5)`
- Returns `MultiAgentRunResponse(result: AgentResult, delegation_trace: list[str])`

### 7. Demo

Create `learning/18-multi-agent/research_demo.py`:
- Builds supervisor with `ResearcherAgent` and `WriterAgent`
- Runs a "research and summarize" task end-to-end
- Prints delegation trace and final output
