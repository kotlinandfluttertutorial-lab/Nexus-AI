## Agent Execution Lifecycle

```
AgentTask (structured input)
    ↓
Task Understanding
    ↓
Context Collection
    ↓
Planning  (AI decides next action)
    ↓
Tool Selection + Validation
    ↓
Tool Execution  (with timeout)
    ↓
Observation  (record result)
    ↓
Next Step Decision
    ↓
Completion / StepLimit / Cancellation / Error
```

## Implementation Task

- `AgentTask` — structured task input model
- `AgentResult` — sealed type (Completed, StepLimitReached, Cancelled, Failed)
- `AgentError` — sealed error hierarchy
- `AgentContext` — maintains observations, bounded window
- `AgentConfig` — maxSteps, stepTimeoutMs, totalTimeoutMs
- `AgentEngine` — execution loop with enforced limits and cancellation
- ViewModel integration for UI state exposure
- Tool registry integration (uses `ApplicationTool` interface only)

## Rules

- **No uncontrolled recursion.** Always use `while (steps < config.maxSteps)`.
- Enforce per-step timeout with `withTimeout`.
- Validate tools before execution — reject unknown tool names with a structured error.
- Support coroutine cancellation — never catch `CancellationException` without rethrowing.
- Keep agent logic entirely in Domain/Data — no Compose imports.
- Agents call Orchestration for AI decisions, never the provider directly.
- Agents call `ApplicationTool.execute()`, never MCP transport directly.

## Test Requirements

- `AgentEngine` happy-path tests (completes within steps)
- Step limit enforcement tests (always reaches `StepLimitReached` when AI never completes)
- Cancellation tests (job cancelled mid-execution)
- Per-step timeout tests
- Tool failure handling tests
- Tool not found tests
- Multi-step execution with observation accumulation
- All tests use `FakeAIProvider` and `FakeTool` from `core/testing/`
