## Implementation Task

Implement the common application-level Tool architecture that bridges MCP, agents, and
orchestration:

- `ApplicationTool` interface (name, description, inputSchema, execute)
- `ToolInput` — typed, validated input container
- `ToolOutput` — typed result container
- `ToolSchema` — input parameter schema with required fields
- `ToolError` — sealed error hierarchy (MissingParameter, InvalidParameter, ExecutionFailed,
  Timeout, NotFound)
- `ToolRegistry` — register, resolve by name, list all, mark unavailable
- `MCPToolAdapter` — implements `ApplicationTool`, wraps `MCPClient` invocation
- Input validation enforced before execution
- Timeout enforced on every execution

## Security Requirements

- Validate tool names — reject unknown tools before attempting execution.
- Validate all required parameters against `ToolSchema` — reject with `ToolError.MissingParameter`.
- Enforce timeout on every `execute()` call — no open-ended tool invocations.
- Never execute arbitrary, unvalidated tool input from an AI model.
- Do not expose internal system paths, secrets, or stack traces in `ToolError` responses.
- Standardize all failures through `ToolError` — callers never see raw exceptions.

## Test Requirements

- `ApplicationTool` interface contract tests
- `ToolInput` validation tests (missing required params, invalid values, oversized values)
- `ToolRegistry` tests (register, resolve, resolve unknown, mark unavailable)
- `MCPToolAdapter` tests:
  - valid invocation → success
  - missing required parameter → `ToolError.MissingParameter`
  - timeout → `ToolError.Timeout`
  - MCP invocation failure → `ToolError.ExecutionFailed`
- `FakeTool` used in agent integration tests
- Timeout enforcement tests
