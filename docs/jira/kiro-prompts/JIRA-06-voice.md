## Target Flow

```
Voice UI
    ↓
Permission Check
    ↓
Speech-to-Text (Android SpeechRecognizer or equivalent)
    ↓
Text Result
    ↓
Chat submission (reuse existing Chat use case)
```

## Implementation Task

Create a lifecycle-safe voice input flow:

- Voice input start/stop controls
- Microphone permission request and rationale
- Speech-to-text result capture
- Result submission into the existing Chat flow
- Lifecycle-safe resource management (no microphone leaks)
- Loading, success, permission-denied, and failure states

## Acceptance Criteria

| # | Criterion |
|---|---|
| AC1 | Voice input can start and stop. |
| AC2 | Microphone permission is requested and handled. |
| AC3 | Speech-to-text result is captured correctly. |
| AC4 | Voice input result can be submitted to Chat. |
| AC5 | Lifecycle changes (rotation, backgrounding) are handled safely. |
| AC6 | Permission denial and recognition failure states are handled explicitly. |

## Rules

- Do not leak microphone resources across lifecycle events.
- Handle `onDestroy` and coroutine cancellation — stop recognition cleanly.
- Do not place business logic inside composables.
- Reuse the Chat flow — do not create a second parallel AI submission path.
- Handle permission denial with a user-visible explanation, not a silent failure.

## Test Requirements

- Permission state tests (granted, denied, rationale needed)
- Voice start/stop tests
- Lifecycle handling tests
- Recognition failure tests
- ViewModel/use-case tests
- Compose interaction tests where appropriate
