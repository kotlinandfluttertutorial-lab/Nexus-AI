## Architecture Rules

- `LLMProvider` is a `Protocol` in the domain layer — never imports SDK types.
- Provider adapters (OpenAI, Gemini) live in `backend/fastapi-service/infrastructure/providers/`.
- Callers inject the provider via FastAPI `Depends` — never instantiate it in a route.
- Streaming uses `AsyncIterator[StreamChunk]` — not provider-specific streaming types.
- Provider errors are caught inside the adapter and mapped to domain error types.
- Active provider is selected from environment configuration — not hardcoded.

## Implementation Task

### 1. Domain Interface

Define in `backend/fastapi-service/domain/interfaces/llm_provider.py`:

```
LLMProvider Protocol:
  - complete(request: ChatRequest) -> ChatResponse
  - stream(request: ChatRequest) -> AsyncIterator[StreamChunk]
```

### 2. Provider Adapters

Implement in `backend/fastapi-service/infrastructure/providers/`:
- `OpenAIProvider` — wraps `openai` SDK
- `GeminiProvider` — wraps `google-generativeai` SDK

Both must implement `LLMProvider`. Neither may expose SDK types outside their file.

### 3. Provider Factory

Wire active provider from `settings.default_provider` environment variable.

### 4. FastAPI Endpoint

Update or create `POST /v1/chat/completions` to:
- Accept non-streaming and streaming requests
- Delegate to the injected `LLMProvider`
- Return `ChatResponse` or SSE stream

### 5. Fake Provider

Create `FakeLLMProvider` in `backend/fastapi-service/tests/fakes/` returning deterministic
responses — used in all tests.
