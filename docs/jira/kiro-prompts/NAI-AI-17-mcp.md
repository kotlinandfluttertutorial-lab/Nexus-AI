## Architecture Rules

- MCP transport types never appear in domain, agent, or API layers.
- MCP tools are converted to `ToolDefinition` objects and registered in `ToolRegistry`.
- Agent runtime calls tools by name through `ToolRegistry` — it has no awareness of MCP transport.
- All tool inputs are validated against the discovered JSON schema before execution.
- Timeouts are enforced per tool call via `asyncio.wait_for`.
- Connection lifecycle (connect, disconnect, reconnect on failure) is managed by `MCPClientManager`.

## Implementation Task

### 1. MCP Client Manager

Create `backend/mcp/clients/mcp_client_manager.py`:
- Constructor: `(server_url: str, api_key: str | None = None)`
- `connect()` — establishes MCP session
- `disconnect()` — closes cleanly
- `is_connected() -> bool`
- `list_tools() -> list[MCPToolInfo]` — fetches tool catalogue from server
- `call_tool(name: str, arguments: dict, timeout: float) -> MCPToolResult`
- Reconnect on `ConnectionError` with exponential backoff (max 3 retries)

### 2. MCP Tool Adapter

Create `backend/mcp/adapters/mcp_tool_adapter.py`:
- `to_tool_definition(mcp_tool: MCPToolInfo) -> ToolDefinition`
- Maps MCP tool name, description, and input schema to the `ToolDefinition` model from NAI-AI-11
- `execute_fn` in `ToolDefinition` calls `mcp_client_manager.call_tool()`
- MCP errors are caught and mapped to `ToolError` domain type

### 3. MCP Resources

MCP Resources are read-only context items (files, URIs, database records) that a server exposes
separately from Tools. Add resource support to `MCPClientManager`:

```python
list_resources() -> list[MCPResourceInfo]
read_resource(uri: str) -> MCPResourceContent
```

Create `backend/mcp/adapters/mcp_resource_adapter.py`:
- Converts `MCPResourceInfo` to a `ResourceDefinition` domain model (uri, name, description, mime_type)
- `read()` calls `client_manager.read_resource(uri)` and returns `ResourceContent`

Add a sample resource to `backend/mcp/servers/demo_server.py` (e.g. `file://readme` returning project description text).

### 4. MCP Server (simple Python server)

Create `backend/mcp/servers/demo_server.py`:
- Implements at least one tool: `get_weather(location: str) -> str`
- Uses the Python MCP SDK to expose the tool
- Runnable standalone: `python demo_server.py`

### 5. MCP Integration with Agent

Create `backend/mcp/integration/mcp_tool_loader.py`:
- `load_tools(client_manager: MCPClientManager, registry: ToolRegistry) -> int`
- Calls `list_tools()`, converts each to `ToolDefinition`, registers in `ToolRegistry`
- Returns number of tools loaded

### 6. FastAPI Endpoints

Add `backend/fastapi-service/api/routers/mcp.py`:
- `GET /v1/mcp/tools` — list discovered MCP tools (requires auth)
- `POST /v1/mcp/tools/{tool_name}/invoke` — invoke a tool by name (requires auth)
- `GET /v1/mcp/resources` — list discovered MCP resources (requires auth)
- `GET /v1/mcp/resources/{resource_uri}` — read a resource by URI (requires auth)

### 7. Fake MCP Transport

Create `backend/mcp/tests/fake_mcp_client.py`:
- Configurable list of fake tools
- Configurable response per tool name
- Configurable error response for testing error mapping

## Acceptance Criteria

| # | Criterion |
|---|---|
| AC1 | `MCPClientManager` connects to an MCP server and `is_connected()` returns `True`. |
| AC2 | `list_tools()` returns the server's available tool catalogue. |

| AC4 | Tool input is validated against the discovered JSON schema before `call_tool()` is invoked. |
| AC5 | Connection lifecycle (connect, disconnect, reconnect with backoff) is handled. |
| AC6 | MCP errors are mapped to domain `ToolError` types — not raw transport exceptions. |
| AC7 | `asyncio.wait_for` timeout is enforced on every `call_tool()`. |
| AC8 | A demo MCP server exposes at least one tool and at least one resource; it is runnable standalone. |
| AC9 | `list_resources()` returns the server's available resource catalogue. |
| AC10 | `read_resource(uri)` returns the resource content; a `ResourceDefinition` adapter model is defined. |
| AC11 | MCP transport types do not appear in `domain/`, `api/`, or `agent-runtime/agents/`. |
| AC12 | Tests use `FakeMCPClient` — no real MCP server required in the test suite. |
