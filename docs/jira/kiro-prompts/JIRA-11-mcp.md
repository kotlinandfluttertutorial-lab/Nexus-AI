## Architecture Boundary

```
Agent / AI Orchestration  (Domain)
    ↓
ApplicationTool  (Domain — common tool abstraction)
    ↓
MCPToolAdapter  (Data — implements ApplicationTool)
    ↓
MCPClient  (Data — transport abstraction interface)
    ↓
MCPTransport  (Data — stdio / SSE / WebSocket)
```

**Compose must never import MCP transport or MCP adapter types.**

## Implementation Task

Implement MCP integration:

- `MCPServerConfig` — server connection configuration model
- `MCPClient` interface — connection lifecycle, discovery, invocation
- `MCPTransport` implementations (at minimum one: SSE or stdio per spec)
- `MCPToolDefinition` — tool metadata from server
- `MCPToolAdapter` — converts `MCPToolDefinition` + `MCPClient` into `ApplicationTool`
- `MCPServerManager` — manages connect/disconnect, tool registration
- Error types: `MCPError` sealed hierarchy
- Input validation before every invocation
- Timeout and coroutine cancellation support

## Security Requirements

- Validate tool names and input schemas before invocation.
- Validate all required parameters — reject missing/invalid input with a structured error.
- Apply timeouts — no open-ended MCP calls.
- Never blindly execute arbitrary tool input from an AI model.
- Do not expose raw transport exceptions to UI or Domain.
- Do not log MCP server credentials or sensitive tool arguments.

## Test Requirements

- Server configuration tests
- Connection lifecycle tests (connect, disconnect, reconnect)
- Capability discovery tests
- Tool discovery tests
- `MCPToolAdapter` tests (input validation, invocation, timeout, error mapping)
- `MCPServerManager` tests
- Cancellation tests
- Error mapping tests (all `MCPError` subtypes)
- All tests use `FakeMCPClient` from `core/testing/`
