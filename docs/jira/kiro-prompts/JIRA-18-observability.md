## Implementation Task

Standardize observability across Nexus AI:

- Logging conventions (`NexusLogger` wrapper or standard tags per module)
- Sensitive data redaction/filtering in all log paths
- AI operation diagnostics (request ID, provider, latency, token count — never content)
- MCP/tool operation diagnostics (tool name, duration, result code — never sensitive args)
- Agent step diagnostics (step number, tool selected, outcome — never conversation content)
- Performance metrics capture (embedding time, inference time, retrieval latency)
- Crash/error monitoring integration (Firebase Crashlytics or per-spec tool)
- Production logging restrictions (`BuildConfig.DEBUG` guards, ProGuard rules)

## Acceptance Criteria

| # | Criterion |
|---|---|
| AC1 | Application logging is standardized with consistent tags and levels. |
| AC2 | Sensitive information (API keys, tokens, prompts, conversation content) is excluded from all log paths. |
| AC3 | AI operations can be diagnosed (latency, provider, error code). |
| AC4 | MCP and tool operations can be diagnosed (tool name, duration, success/failure). |
| AC5 | Important performance metrics can be captured and inspected. |
| AC6 | Errors and crashes can be integrated with the selected monitoring solution. |
| AC7 | Production builds have appropriately restricted logging (no DEBUG/VERBOSE in release). |

## Security Requirements (Non-Negotiable)

Never log:
- API keys or auth tokens
- Passwords or PINs
- JWT payloads
- Sensitive document content
- Conversation message content
- AI prompt text
- Sensitive tool input parameters (file paths, PII, credentials)

All log statements that could contain dynamic data must pass through a redaction check or
use structured fields that exclude sensitive values.

## Test Requirements

- Logging behavior tests (correct level, correct tag, correct structure)
- Sensitive-data filtering tests (verify redaction works)
- Error reporting tests (verify errors reach the monitoring integration)
- Performance metric capture tests
- Production restriction tests (verify DEBUG logs are absent from release build config)
