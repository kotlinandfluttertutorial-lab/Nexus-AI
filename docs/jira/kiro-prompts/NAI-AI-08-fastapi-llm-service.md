## Architecture Rules

- All routes have typed `response_model` and Pydantic request bodies.
- Services are injected via FastAPI `Depends` — never instantiated in route handlers.
- All settings come from `pydantic-settings` — no hardcoded values.
- Provider SDK types stay inside `infrastructure/providers/` — never appear in `api/` or `domain/`.
- Streaming uses `StreamingResponse` with `media_type="text/event-stream"`.
- API key validation is a FastAPI dependency applied to all inference routes.
- Error responses follow: `{"detail": {"code": "...", "message": "..."}}`.

## Implementation Task

### Required Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | /v1/chat/completions | Yes | Non-streaming and streaming chat |
| POST | /v1/embeddings | Yes | Generate embeddings for input texts |
| GET | /v1/models | Yes | List configured models |
| GET | /health | No | Liveness probe |
| GET | /readiness | No | Readiness probe (checks provider reachability) |

### Required Components

1. **Pydantic Models** (`domain/models/`):
   - `Message`, `ChatRequest`, `ChatResponse`, `StreamChunk`
   - `EmbeddingRequest`, `EmbeddingResponse`
   - `HealthResponse`, `ReadinessResponse`

2. **Routers** (`api/routers/`):
   - `chat.py`, `embeddings.py`, `models.py`, `health.py`

3. **Auth Middleware** (`api/middleware/auth.py`):
   - `verify_api_key` dependency; reads `APP_API_KEY` from settings
   - Applied via `Depends` on all inference routes

4. **Services** (`application/services/`):
   - `ChatService`: delegates to `LLMProvider`; handles streaming lifecycle
   - `EmbeddingService`: delegates to embedding provider

5. **Settings** (`infrastructure/config.py`):
   - All keys via `pydantic-settings`; `.env.example` documents every key

6. **OpenAPI Customization** (`main.py`):
   - `title`, `description`, `version` set on `FastAPI()`
   - Tags applied to all routers
