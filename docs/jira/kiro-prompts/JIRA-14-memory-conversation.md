## Implementation Task

Implement conversation memory persistence:

- `Conversation` domain entity (id, title, createdAt, updatedAt)
- `Message` domain entity (id, conversationId, content, role, timestamp)
- `ConversationRepository` interface (Domain)
- `MessageRepository` interface (Domain)
- Room entities, DAOs, and migrations (Data)
- Repository implementations (Data)
- Use cases: CreateConversation, GetConversations, GetMessages, RenameConversation,
  DeleteConversation, SaveMessage
- All Room operations via `suspend` functions and `Flow`

## Rules

- Room entities and DAOs belong in the Data layer — never in Domain.
- Repository interfaces belong in Domain — `ConversationRepository`, `MessageRepository`.
- ViewModels inject use cases, not DAOs or repositories directly.
- Never use `fallbackToDestructiveMigration()` — write proper Room migrations.
- Do not perform blocking database operations on the main thread.
- Do not log full conversation message content — it may be sensitive.

## Test Requirements

- DAO tests with in-memory Room database (`Room.inMemoryDatabaseBuilder`)
- Repository implementation tests
- Use case tests with `FakeConversationRepository` and `FakeMessageRepository`
- Migration tests (verify schema evolution preserves existing data)
- Rename and delete operation tests
- History loading tests (Flow emissions)
- Coroutine dispatch tests
