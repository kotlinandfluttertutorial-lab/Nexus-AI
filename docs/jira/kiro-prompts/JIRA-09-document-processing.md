## Target Pipeline

```
Document selection (SAF / file picker)
    ↓
Metadata capture (name, size, MIME type, URI)
    ↓
Text extraction (PDF, DOCX, TXT, etc.)
    ↓
Content normalization (whitespace, encoding cleanup)
    ↓
Observable processing status (Pending → Indexing → Ready / Failed)
```

## Implementation Task

Implement the document ingestion pipeline that feeds downstream RAG (JIRA-10):

- Android document picker integration
- Document metadata model (`Document` entity)
- Text extractor per supported MIME type
- Content normalizer
- Processing status observable via Flow
- Background-safe extraction (does not block main thread)
- Error handling for unsupported formats and malformed documents

## Acceptance Criteria

| # | Criterion |
|---|---|
| AC1 | User can select supported document types. |
| AC2 | Document metadata is captured and persisted. |
| AC3 | Text can be extracted from supported formats. |
| AC4 | Extracted content is normalized. |
| AC5 | Processing does not block the UI thread. |
| AC6 | Processing status is observable via Flow/StateFlow. |
| AC7 | Extraction failures produce structured errors, not crashes. |
| AC8 | Unit tests cover document-processing logic. |

## Rules

- Never perform expensive extraction on the main/UI thread.
- Preserve document metadata (ID, source URI, MIME type, page count where available)
  as this is required by RAG (JIRA-10).
- Validate supported MIME types before attempting extraction.
- Handle malformed and unsupported documents with structured `DocumentError` types.
- Do not log document content — it may be sensitive.

## Test Requirements

- Document metadata capture tests
- Extraction tests per supported format (use sample test files)
- Normalization tests (whitespace, encoding edge cases)
- Failure tests (unsupported format, malformed file, extraction error)
- Coroutine/background dispatch tests
- ViewModel and use case tests
- Status observable (Flow) tests
