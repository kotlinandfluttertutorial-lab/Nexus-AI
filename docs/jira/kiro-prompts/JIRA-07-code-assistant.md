## Implementation Task

Support code-focused AI operations using the existing AI provider abstraction:

- Submit code snippet for AI processing
- Explain code operation
- Debug code operation
- Improve/refactor code operation
- Preserve code formatting (monospace, indentation, whitespace)
- Handle long-running AI operations with loading state
- Handle errors with user-safe messages

## Acceptance Criteria

| # | Criterion |
|---|---|
| AC1 | User can submit a code snippet. |
| AC2 | Explain-code operation is supported and returns an explanation. |
| AC3 | Debug and improve/refactor operations are supported. |
| AC4 | Code formatting (indentation, whitespace) is preserved in display. |
| AC5 | AI provider remains abstracted — no provider SDK in UI or Domain. |
| AC6 | Long-running and error states are handled with appropriate UI feedback. |
| AC7 | Business logic (use cases, ViewModel) is unit tested. |

## Rules

- Do not put AI or provider logic inside Compose.
- Reuse existing `AIRequest`/`AIResponse` abstractions — do not create parallel AI types.
- Avoid duplicating Chat infrastructure; extend or compose it where appropriate.
- Preserve code text exactly — do not trim, normalize, or transform whitespace unexpectedly.
- Do not log submitted source code unnecessarily — it may be sensitive.

## Test Requirements

- Use case tests (explain, debug, improve operations)
- ViewModel state transition tests
- Request construction tests (correct prompt structure per operation)
- Code formatting preservation tests
- Loading/error state tests
- `FakeAIProvider` used in all AI-touching tests
- Compose interaction tests where appropriate
