## Implementation Task

Integrate on-device AI through the common `AIProvider` / `AIStreamClient` domain interfaces:

- `OnDeviceAIProvider` implementing `AIProvider` and `AIStreamClient`
- Device capability detection (`OnDeviceModelManager`)
- Lifecycle-safe model initialization and warm-up
- Offline inference (no network required)
- Streaming support where the on-device framework supports it
- Configurable cloud fallback (explicit, not automatic)
- Failure handling: model not available, initialization failed, inference failed

## Acceptance Criteria

| AC8 | Capability detection and inference logic are covered by unit tests. |

## Rules

- Do not assume every device can run the model — always check capability first.
- Never block the UI thread during model initialization or inference.
- Model loading, warm-up, and lifecycle management happen inside the provider implementation.
- Cloud fallback must be explicit and configurable (DataStore setting or build config).
  Never fall back silently or automatically without user-visible configuration.
- On-device providers must handle the "model not yet downloaded" case explicitly.
- Do not expose local model file paths or internal inference details to UI.

## Test Requirements

- Streaming event tests
- Failure tests (model unavailable, inference error)
- Lifecycle and cancellation tests
- Cloud fallback trigger tests
