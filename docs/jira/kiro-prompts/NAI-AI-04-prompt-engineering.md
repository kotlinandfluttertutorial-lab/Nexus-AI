## Architecture Rules

- Prompt templates live in `backend/fastapi-service/application/prompts/` as versioned files or
  constants — never inline strings inside route handlers or service methods.
- Template variables are explicitly named and documented.
- Output validation uses JSON schema or Pydantic — never regex on freeform output.
- Input size limits are enforced before the prompt is sent to the LLM.
- Prompt injection mitigations: sanitize user-supplied content embedded in templates
  (strip control characters, enforce max length per input variable).

## Implementation Task

### 1. Template System

Create a `PromptTemplate` class or dict-based registry with:
- Template ID and version
- Raw template string with named `{variable}` placeholders
- `render(variables: dict) -> str` method
- Input size validation per variable (max character/token count)

### 2. Prompt Strategies

Implement and demonstrate in `learning/04-prompt-engineering/`:
- **Zero-shot**: direct instruction, no examples
- **Few-shot**: 2–3 examples in the prompt
- **Role-based**: system prompt sets a specific persona
- **Structured output**: prompt instructs the model to return JSON matching a schema

### 3. Output Validation

Validate structured responses against a Pydantic model.
Return a structured error when the response does not match.

### 4. Prompt Workbench

Create `learning/04-prompt-engineering/workbench.py` or equivalent that:
- Iterates over a set of prompt test cases
- Calls the `FakeLLMProvider` (and optionally a real provider in integration mode)
- Records the rendered prompt, raw response, and validation result
