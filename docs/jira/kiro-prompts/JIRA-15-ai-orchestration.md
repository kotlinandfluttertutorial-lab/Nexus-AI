## Target Architecture

```
UI
↓
AI Orchestration  (single entry point for all AI capability)
├── AIProvider          — routes to selected provider
├── RAG                 — injects retrieved context
├── AgentEngine         — executes multi-step agent tasks
├── ToolRegistry        — resolves and executes tools
├── Memory              — supplies and persists conversation context
└── MCP Tools           — registered as ApplicationTools
```

## Implementation Task

Create the orchestration layer that coordinates all AI subsystems without Compose dependencies:

- `AIOrchestration` interface (Domain)
- `AIOrchestrationImpl` (Data/AI module)
- Chat request routing with memory context injection
- RAG context retrieval and injection before AI generation
- Agent task routing
- Tool registry coordination
- Streaming lifecycle management
- Error standardization across all subsystems

## Acceptance Criteria

| # | Criterion |

| AC1 | `AIOrchestration` layer exists as a domain interface. |
| AC2 | Chat requests can be routed through orchestration. |

| AC4 | Agent tasks can be routed through orchestration. |
| AC5 | MCP/tool execution can be coordinated. |
| AC6 | Conversation context (memory) can be supplied to AI requests. |
| AC7 | AI errors from all subsystems are standardized. |
| AC8 | Orchestration implementation has zero Compose dependencies. |
| AC9 | End-to-end orchestration scenarios are covered by tests. |

## Rules

- Orchestration must import no Compose types.
- Orchestration must import no provider SDK types.
- Orchestration must not directly access Room, DataStore, or any storage.
- Orchestration must not directly access MCP transport.
- Reuse existing abstractions — do not duplicate provider logic.
- Preserve streaming behavior through orchestration.
- Standardize all failures as `AIError` before surfacing to callers.
