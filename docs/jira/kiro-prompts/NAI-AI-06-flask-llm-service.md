## Architecture Rules

- Use the application factory pattern: `create_app(config_name: str) -> Flask`.
- Group routes into Blueprints: `chat_bp`, `models_bp`, `health_bp`.
- Route handlers delegate to a service layer — no SDK calls inside blueprint functions.
- All configuration (API keys, model names) from `os.environ` via a `Config` class.
- Consistent error responses: `{"error": {"code": "...", "message": "..."}}`.
- SSE streaming uses `flask.Response(generator, mimetype="text/event-stream")`.
- API key authentication on all inference endpoints via a `before_request` guard.

## Implementation Task

### 1. Application Structure

Create `backend/flask-service/` with:
```
app/__init__.py          — create_app() factory
app/config.py            — Config, DevelopmentConfig, ProductionConfig
app/routes/
    chat.py              — Blueprint: POST /v1/chat/completions
    models.py            — Blueprint: GET /v1/models
    health.py            — Blueprint: GET /health
app/services/
    chat_service.py      — calls provider; handles streaming
    provider_factory.py  — builds provider from config
app/errors.py            — register_error_handlers(app)
tests/
    conftest.py
    test_chat.py
    test_models.py
    test_health.py
.env.example
requirements.txt
run.py
```

### 2. Endpoints

| Method | Path | Auth Required | Description |
|---|---|---|---|
| POST | /v1/chat/completions | Yes | Chat completion (streaming supported) |
| GET | /v1/models | Yes | List available model names |
| GET | /health | No | Liveness check |

### 3. Request Validation

- `messages` field is required; return 400 if missing.
- `model` field defaults to `DEFAULT_MODEL` from config.
- `temperature` must be between 0.0 and 2.0 if provided.

### 4. Fake Provider for Tests

Create `tests/fakes/fake_provider.py` returning deterministic responses.
