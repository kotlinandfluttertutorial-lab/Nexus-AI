## Implementation Task

Create an image-generation flow using the AI provider abstraction:

- Image prompt submission
- Image-generation provider implementation (behind the `AIProvider` abstraction)
- Loading state with progress indication
- Generated image display
- Failure state with user-safe error message
- Image saving/sharing where specified in the spec

## Acceptance Criteria

| # | Criterion |
|---|---|
| AC1 | User can submit an image generation prompt. |
| AC2 | Image-generation provider is abstracted behind the domain interface. |
| AC3 | Loading state is displayed during generation. |
| AC4 | Generated image is displayed correctly. |
| AC5 | Failure state is displayed with a user-safe message. |
| AC6 | Provider implementation remains isolated — no SDK types in Domain or UI. |

## Rules

- Do not expose provider SDK models (URLs, binary data wrappers) to UI or Domain directly.
- Reuse existing `AIProvider`/`AIRequest` abstractions — extend them for image generation rather than creating parallel types.
- Keep image-generation provider code entirely within the Data layer.
- Handle loading, success, and failure as explicit sealed states.
- Do not store API keys in source code — use the established secrets mechanism.
