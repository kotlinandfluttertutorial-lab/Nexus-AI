## Implementation Task

Establish a CI/CD validation pipeline for Nexus AI:

- GitHub Actions workflow(s) for pull request and push-to-main triggers
- Unit test execution step (`./gradlew testDebugUnitTest`)
- Android debug build step (`./gradlew assembleDebug`)
- Lint/static analysis step (`./gradlew lint`)
- Compose/instrumented test step (on emulator or test lab)
- Secret handling via GitHub Actions secrets (never committed to repo)
- Pipeline failure on critical test/build/lint errors
- Visible CI results in PR checks

## Acceptance Criteria

| # | Criterion |
|---|---|
| AC1 | Unit tests execute automatically in CI on PR and push. |
| AC2 | Android debug build executes in CI. |
| AC3 | Static analysis/lint executes in CI. |
| AC4 | Critical test or build failures fail the pipeline (non-zero exit). |
| AC5 | Secrets are externalized via GitHub Actions secrets — not committed to source. |
| AC6 | Debug build validation evidence is visible in CI output. |
| AC7 | Relevant Compose/UI tests are included in the CI run. |
| AC8 | CI results are visible in pull request checks. |

## Rules

- Never commit production secrets, API keys, or credentials to the repository.
- Do not weaken or skip tests to make CI green — fix the underlying issue.
- Keep CI deterministic where possible — avoid flaky tests.
- Reuse existing Gradle tasks — do not duplicate build logic.
- Ensure build/test failures produce visible, actionable output in CI logs.
- Follow `.kiro/steering/07-git-standards.md` — CI must pass before merge.

## Test Requirements

Run locally before pushing CI configuration:
- `./gradlew testDebugUnitTest` — all unit tests pass
- `./gradlew assembleDebug` — debug build succeeds
- `./gradlew lint` — lint passes without new errors
- Verify workflow YAML syntax is valid
