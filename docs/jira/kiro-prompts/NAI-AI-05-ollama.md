## Architecture Rules

- `OllamaProvider` lives in `backend/fastapi-service/infrastructure/providers/ollama_provider.py`.
- It implements `LLMProvider` — no Ollama-specific types leak outside the file.
- `OLLAMA_BASE_URL` defaults to `http://localhost:11434` and is overridable from environment.
- The adapter uses `httpx.AsyncClient` — not the Ollama Python SDK if it conflicts with the
  project's async pattern.
- Health check calls `GET /api/tags` — a successful response means Ollama is ready.
- Latency is measured using `time.perf_counter()` and logged at DEBUG level.

## Implementation Task

### 1. Ollama Setup (local)

Document in `learning/05-ollama/README.md`:
- How to install Ollama
- How to pull a model: `ollama pull llama3.2` (or equivalent small model)
- How to verify: `ollama list` and `curl http://localhost:11434/api/tags`

### 2. OllamaProvider Adapter

Implement `OllamaProvider` using `httpx.AsyncClient` calling:
- `POST /api/chat` for non-streaming completion
- `POST /api/chat` with `"stream": true` for streaming

Map Ollama response to `ChatResponse` / `StreamChunk` domain types.
Map Ollama HTTP errors (connection refused, 404 model not found) to domain `AIError` types.

### 3. Model Selection

Support model name selection via `ChatRequest.model` field.
Default model is configured via `OLLAMA_DEFAULT_MODEL` environment variable.

### 4. Latency Measurement

Wrap each `complete()` and `stream()` call with timing.
Log: `OllamaProvider: completed in {elapsed_ms:.0f}ms, model={model}`.

### 5. OpenAI-Compatible API Mode

Document and demonstrate in `learning/05-ollama/openai_compat_demo.py`:
- Ollama exposes `http://localhost:11434/v1/` as an OpenAI-compatible endpoint.
- Instantiate the `openai` Python SDK with `base_url="http://localhost:11434/v1"` and `api_key="ollama"`.
- Make a `client.chat.completions.create()` call — show that the same SDK code works with a local model.
- This proves Ollama's drop-in compatibility for any OpenAI SDK integration.

### 6. Health Check

Add a `ping() -> bool` method that calls `GET /api/tags` and returns `True` if Ollama is reachable.
Wire this into the `/readiness` endpoint.
