## Architecture Rules

- Evaluation datasets are versioned JSON files — never overwrite existing versions.
- Judge LLM must use `temperature=0` for reproducible scoring.
- `EvaluationReport` records: `run_id`, `timestamp`, `model_version`, `dataset_version`, all metric scores.
- Evaluation never calls real LLM APIs in the unit test suite — use `FakeLLMProvider` as judge.
- Production user data is never used as evaluation data without explicit anonymization.
- Reports are stored as JSON in `backend/evaluation/reports/`.

## Implementation Task

### 1. RAG Evaluation Dataset

Create `backend/evaluation/datasets/rag_eval_v1.json`:
```json
{
  "version": "1.0",
  "description": "Nexus AI RAG evaluation — general knowledge",
  "items": [
    {
      "id": "q001",
      "question": "What is retrieval-augmented generation?",
      "reference_answer": "RAG retrieves relevant documents and injects them into an LLM prompt.",
      "relevant_document_ids": ["doc_001"]
    }
  ]
}
```
Include at least 10 items with representative questions.

### 2. Agent Evaluation Dataset

Create `backend/evaluation/datasets/agent_eval_v1.json`:
```json
{
  "version": "1.0",
  "description": "Nexus AI agent task completion evaluation",
  "items": [
    {
      "id": "t001",
      "task": "Find and summarize information about vector databases.",
      "success_criteria": "Response mentions at least one vector database by name."
    }
  ]
}
```
Include at least 5 tasks.

### 3. RAG Metrics

Create `backend/evaluation/metrics/rag_metrics.py`:
- `compute_faithfulness(answer, context, judge_llm) -> float` — proportion of claims supported by context
- `compute_answer_relevance(question, answer, judge_llm) -> float` — does answer address question
- `compute_context_precision(question, retrieved_chunks, relevant_ids) -> float` — precision@K
- `compute_context_recall(relevant_ids, retrieved_ids) -> float` — recall@K

### 4. Agent Metrics

Create `backend/evaluation/metrics/agent_metrics.py`:
- `compute_task_completion_rate(results: list[AgentResult]) -> float`
- `compute_avg_steps(results: list[AgentResult]) -> float`
- `compute_step_limit_hit_rate(results: list[AgentResult]) -> float`

### 4. Hallucination Detection Metric

Create `backend/evaluation/metrics/hallucination_metrics.py`:
- `compute_hallucination_score(answer: str, context: list[str], judge_llm) -> float`
  — asks judge LLM to identify claims in the answer that are NOT supported by the context.
  Returns proportion of unsupported claims (0.0 = no hallucination; 1.0 = fully hallucinated).
- `compute_groundedness(answer: str, reference_answer: str, judge_llm) -> float`
  — compares the answer against the reference answer for factual consistency.

Document in `README.md`: how to construct ground-truth reference answers and why ground truth quality directly impacts metric reliability.

### 5. Operational Metrics

Create `backend/evaluation/metrics/operational_metrics.py`:
- `OperationalMetrics` dataclass: `response_time_ms`, `prompt_tokens`, `completion_tokens`, `cost_usd`
- `compute_percentiles(times: list[float]) -> dict` — returns p50, p95, p99

### 6. Evaluation Runners

Create `backend/evaluation/runners/`:
- `rag_evaluator.py` — runs each dataset item through the RAG pipeline; computes all RAG metrics; records operational metrics
- `agent_evaluator.py` — runs each task through the agent; records `AgentResult` and operational metrics

### 7. Report Generator

Create `backend/evaluation/reports/report_generator.py`:
- Accepts `list[RAGEvalResult]` or `list[AgentEvalResult]`
- Produces `EvaluationReport` with summary statistics
- Saves to `backend/evaluation/reports/{run_id}.json`

### 8. FastAPI Dashboard Endpoint

Add `GET /v1/evaluation/reports` — lists available report IDs and dates.
Add `GET /v1/evaluation/reports/{run_id}` — returns full `EvaluationReport`.
