## Architecture Rules

- Secrets come from Google Secret Manager at runtime — never baked into Docker image layers.
- Container runs as a non-root user.
- Image tags reference an exact SHA or versioned tag — never `latest` in production.
- All log output is newline-delimited JSON with `severity`, `message`, `timestamp`, and `service`.
- Cloud Run service account has minimum required IAM roles only.
- Rollback is a single `gcloud run services update-traffic` command — must be demonstrated.
- `.env` files are never committed; `.env.example` with placeholder values is committed.

## Implementation Task

### 1. Dockerfile

Create `infrastructure/docker/fastapi.Dockerfile`:
- Base: `python:3.11-slim`
- Layer order: system deps → `requirements.txt` → application code
- Non-root user: `adduser --disabled-password appuser && USER appuser`
- `EXPOSE 8080`
- `CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8080"]`

### 2. Docker Compose (local stack)

Create `infrastructure/docker/docker-compose.yml`:
- Services: `fastapi`, `chroma`
- Mounts `.env` file; Chroma uses a named volume for persistence
- Health check: `curl -f http://localhost:8080/health`

### 3. Structured JSON Logging

Create `backend/fastapi-service/infrastructure/logging.py`:
- `CloudLoggingFormatter` as per the `deployment` skill pattern
- `configure_logging()` called from `main.py` startup
- Verify with `docker run` that stdout is valid JSON

### 4. Cloud Run Service YAML

Create `infrastructure/cloud-run/fastapi-service.yaml`:
- `autoscaling.knative.dev/minScale: "1"` / `maxScale: "10"`
- Resources: `cpu: "2"`, `memory: "1Gi"`
- Secret env var for `OPENAI_API_KEY` from Secret Manager
- Service account: `nexus-ai-sa@PROJECT_ID.iam.gserviceaccount.com`

### 5. GitHub Actions Pipeline

Create `infrastructure/ci-cd/build-push.yml`:
- Trigger: push to `main`
- Steps: checkout → authenticate to GCR → build image → push with `${{ github.sha }}` tag

Create `infrastructure/ci-cd/deploy.yml`:
- Trigger: workflow_call from `build-push.yml`
- Steps: deploy to staging (`--no-traffic`) → health check → shift traffic
- Secrets: `GCP_SA_KEY` from GitHub Secrets

### 6. Environment Configuration

Create `infrastructure/deployment/environments/`:
- `local.env.example` — all keys with placeholder values
- `staging.env.example`
- `production.env.example`

Document which keys come from Secret Manager vs. Cloud Run env vars.

### 7. Runbook

Create `infrastructure/deployment/runbook.md`:
- Prerequisites (gcloud, docker, auth setup)
- Deploy to staging: step-by-step
- Promote to production: step-by-step
- Rollback procedure: exact `gcloud` command
- Health verification: `curl /health` and `curl /readiness`
- Monitoring: where to find logs in Cloud Console
