## Implementation Task

Establish or standardize WorkManager-based background processing for Nexus AI:

- `CoroutineWorker` implementations for long-running work (document indexing, embedding)
- Hilt WorkManager integration (`@HiltWorker`) for all workers
- Explicit `Constraints` per worker (network required, battery not low, etc.)
- Observable work status via `WorkInfo` Flow / `StateFlow`
- Retry policy per worker (`Result.retry()` with max attempts)
- Failure representation (`Result.failure()` with output data)
- Idempotency where practical (re-running a worker produces the same result)

| AC7 | UI remains responsive — no background worker blocks the main thread. |

## Rules

- Use WorkManager only for work that genuinely needs to survive UI lifecycle changes.
  Do not use it for work that must complete immediately in the foreground.
- Use `CoroutineWorker` for all suspend-based work.
- Inject dependencies with `@HiltWorker` and `@AssistedInject`.
- Define `Constraints` explicitly — do not run intensive work when battery is low.
- Never block `Dispatchers.Main` from a worker.
- Make work idempotent where practical — safe to retry without side effects.
- Expose observable state so UI can reflect job progress without polling.
