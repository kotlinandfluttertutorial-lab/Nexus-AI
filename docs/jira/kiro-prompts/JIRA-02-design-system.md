## Jira Title

Design System

## Required Skills

- android
- compose
- testing

## Pre-Implementation Checklist

Before making any changes:

1. Inspect the repository, `.kiro/steering/`, applicable `.kiro/skills/`, relevant `.kiro/specs/`,
   and existing UI components.
2. Do not create duplicate components if reusable UI already exists.
3. Read `.kiro/skills/compose/SKILL.md` and `.kiro/skills/android/SKILL.md` fully.

## Rules

- Use Jetpack Compose and Material 3 — no Material 2.
- Prefer stateless reusable composables.
- Hoist state where appropriate.
- Keep business logic out of composables.
- Centralize theme, typography, spacing, and shapes.
- Follow accessibility requirements (content descriptions, touch targets).
- Preserve existing application behavior.

## Implementation Task

Establish the Nexus AI design system required by current and future features:

- Material 3 theme (light + dark)
- Typography scale
- Spacing and shape tokens
- Reusable UI components (buttons, inputs, cards, loading indicators, error states)
- Accessibility baseline
- Component previews

## Acceptance Criteria

| # | Criterion |
|---|---|
| AC1 | Material 3 is established. |
| AC2 | Light and dark themes are supported. |
| AC3 | Typography is centralized. |
| AC4 | Spacing and shapes are centralized. |
| AC5 | Reusable UI components are created. |
| AC6 | Components follow accessibility guidelines. |
| AC7 | Compose tests cover important reusable components. |

## Test Requirements

- Compose UI tests for reusable components
- Component rendering tests (initial state, loading, error)
- Interaction tests
- Theme-related tests where appropriate
- Existing unit tests must continue to pass
- Debug build validation
