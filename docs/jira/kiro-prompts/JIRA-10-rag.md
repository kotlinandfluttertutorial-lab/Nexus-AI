## Implementation Task

Implement the full RAG pipeline behind domain repository interfaces:

- `DocumentChunker` — splits normalized text into bounded, overlapping chunks with metadata
- `EmbeddingProvider` interface + implementation
- `VectorStore` interface + implementation
- `IndexDocumentUseCase` — orchestrates chunking → embedding → storage
- `RetrieveContextUseCase` — query embedding → search → bounded context assembly
- `AssembledContext` sealed type (Empty / WithContent + sources)
- Metadata preservation throughout (document ID, chunk ID, page, source)
- Background indexing via WorkManager (reuse JIRA-17 infrastructure where available)

## Acceptance Criteria

| # | Criterion |
|---|---|
| AC1 | Documents can be chunked with metadata preserved. |
| AC2 | Embeddings can be generated per chunk. |
| AC3 | Embeddings and chunks can be stored. |
| AC4 | Semantic similarity search is supported. |
| AC5 | Top-K results can be returned with scores. |

| AC7 | Empty retrieval is handled explicitly — not silently passed as empty context. |
| AC8 | All RAG pipeline stages have unit tests. |

## Rules

- Always bound assembled context size — never pass unbounded text to AI.
- Do not blindly inject all retrieved content — respect the configured token/char budget.
- Keep `EmbeddingProvider` and `VectorStore` implementations replaceable via interfaces.
- Use `FakeEmbeddingProvider` and `FakeVectorStore` from `core/testing/` in all tests.
- Do not couple RAG pipeline logic to Compose or ViewModel.
- Each pipeline stage must handle its own failure with a structured `RAGError` type.

## Test Requirements

- Chunking tests (boundary conditions, overlap, metadata preservation)
- Embedding tests (using `FakeEmbeddingProvider`)
- Vector store upsert and search tests (using `FakeVectorStore`)
- Top-K retrieval tests
- Context assembly tests (bounded by max chars, source metadata present)
- Empty retrieval tests
- Error handling tests per stage (extraction, embedding, vector store, retrieval)
- `IndexDocumentUseCase` end-to-end with fakes
- `RetrieveContextUseCase` end-to-end with fakes
